# RAG框架缺陷特征与修复策略的实证研究

本仓库提供论文《RAG框架缺陷特征与修复策略的实证研究》（*An Empirical Study of Defect Characteristics and Repair Strategies in RAG Frameworks*）的缺陷标注数据、标注手册、样本筛选与指标记录，以及大语言模型候选代码和人工语义审查结果。

**作者：胡文华、陈晓东、杨振、肖艳、向剑文、马传香。**

## 研究范围

本研究分析RAGFlow、AnythingLLM、FastGPT和Kotaemon四个端到端开源RAG框架自身的软件缺陷，覆盖相关实现及其维护的配置、依赖声明和部署设置。研究以Issue–PR关联样本为单位，从缺陷症状、功能阶段、根因、修复投入及小规模修复策略等维度展开分析，并探索大语言模型生成局部候选修复代码的能力。

| 框架 | 主表样本数 |
| --- | ---: |
| RAGFlow | 160 |
| AnythingLLM | 88 |
| FastGPT | 60 |
| Kotaemon | 25 |
| 合计 | 333 |

## 分类与主要统计

### 缺陷症状与根因

功能失效201条，运行崩溃111条，构建与启动失败11条，性能与成本异常10条。前两类共312条，占93.7%。

| 一级根因 | 样本数 | 其中RAG特有 | RAG特有类内比例 |
| --- | ---: | ---: | ---: |
| 数据处理错误 | 81 | 30 | 37.04% |
| 逻辑与校验错误 | 62 | 11 | 17.74% |
| 接口契约错误 | 52 | 11 | 21.15% |
| 状态一致性错误 | 46 | 13 | 28.26% |
| 依赖与环境错误 | 39 | 5 | 12.82% |
| 资源管理不当 | 26 | 5 | 19.23% |
| 安全漏洞 | 21 | 0 | 0.00% |
| 提示词与上下文错误 | 6 | 2 | 33.33% |
| 合计 | 333 | 77 | 23.12% |

RAG特有根因为77条，占23.12%；通用根因为256条，占76.88%。二级判定考察缺陷是否直接破坏分块、索引、嵌入表示、检索策略或证据上下文组织等RAG处理规则；两类样本可以具有相同的底层错误形式。判定依据及类别边界见标注手册。

### 修复投入与小规模修复

RQ3按记录的排除条件选取317条样本。对应分析脚本的三个指标为：Issue创建至关闭的连续天数、Issue与PR评论合计、关联PR的新增与删除行数之和。中位数分别为3.08天、3条和23行。这些指标是公开可观察的修复投入代理量。

`RQ3_样本与指标.csv`分别保留`issue_comments`、`pr_comments`和`discussion_count`，其中最后一列为前两者之和；不要将合计数解释为单独的Issue评论数。`pr_comments`使用采集时的PR普通评论计数，不另加行内审查评论或Review记录。PR总变更行数未统一剔除测试、文档或格式调整，也不等于人工识别的最小修复行数。

RQ4与RQ5使用筛选后的122项局部修复任务。主表的`fix_strategy`记录九类修复操作，论文归纳的六类小规模修复模式是进一步的定性分析，两者不作机械的一一转换。

## 大语言模型实验

实验使用DeepSeek-V4-Flash和GPT-5.4-mini。每项任务提供Issue信息、缺陷相关路径和修复前局部代码，不提供开发者修复补丁；不联网、不调用工具、不检索仓库，设置`temperature=0`、`top_p=1`，每项任务每个模型生成一次候选代码。

| 模型 | 人工语义审查通过数 | 通过率 |
| --- | ---: | ---: |
| DeepSeek-V4-Flash | 54/122 | 44.3% |
| GPT-5.4-mini | 51/122 | 41.8% |

结果表中的`deepseek_semantic_accepted`与`gpt_semantic_accepted`分别对应原实验记录的`is_fixed`与`is_fixed.1`：`1`为人工语义审查通过，`0`为未通过。候选代码与评价值均保持原始记录。

`deepseek_candidate_code`与`gpt_candidate_code`分别保存两个模型的候选输出。根因标签、根因总结和`how_to_fix_bug`是标注及评价材料，不作为模型生成输入。

人工语义审查判断候选代码是否符合目标修复语义，未执行完整项目构建、缺陷触发与回归测试，因此上述比例不是运行验证后的修复成功率。当前材料可以核查保存的模型输出与最终评价；完整的逐任务API请求、全部局部输入及双人原始独立评分矩阵未包含在本包中，不能据此重放全部生成过程或重新计算标注一致性系数。

## 本地核查

使用Python 3.10或更高版本，在仓库根目录运行：

```bash
python -m pip install -r requirements.txt
python scripts/verify_dataset.py
```

脚本只读本地文件，不访问GitHub或模型API，也不修改标注。它输出框架内数量、比例、全样本与框架等权比例、二级分类统计、RQ3指标和RQ5语义审查结果。该脚本用于基础结果与数据完整性核对，不包含全部论文图形、推断检验或模型调用流程。

## 数据来源与解释

样本来自四个项目公开的GitHub Issue、PR及讨论记录，链接保留在数据表中。时间与评论等元数据反映采集时快照，可能与后续网页不同。主表的整数天数字段作为原始记录保留，连续时间统计由创建与关闭时间戳计算。

根因归因结合Issue、相关实现和针对性修复；部分内部错误状态来自实现逻辑推断。公开反馈可以补充修复效果证据，但Issue关闭或PR合并本身不构成独立运行验证。当前分类和统计基于所收集的四框架样本。
